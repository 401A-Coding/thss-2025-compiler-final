## SysY 语言定义

SysY语言是毕昇杯比赛采用的语言，其实质是 C 语言的子集。SysY 语言的词法规则和语法规则与 PA1、PA3 中的定义一致，更多细节请见 PDF: [SysY语言定义](http://166.111.80.114:8000/labs/pdf/SysY语言定义.pdf)。

```bash
make -j8
```

此时，可以看到`build/`目录下生成了可执行文件`compiler`。

接下来，你可以用你自己实现的`compiler`来编译SysY代码：


生成的`00_main.ll`就是你编译出来的 LLVM IR 文件。你可以使用`clang`将其进一步编译成二进制文件。



```bash
clang 00_main.ll -w -o 00_main
./00_main

# 查看程序返回值

```

当你的 SysY 需要链接 sylib 库时，可以使用下面的命令：


### 类型系统

为了类型检查以及描述 LLVM IR 中的类型信息，我们需要用特定的数据结构描述 SysY 语言中的类型。

如果语言中只存在`int`、`void`这样的基本类型，我们可以用一个简单的枚举来表示类型。

```c++
enum Type {
    IntType,
    VoidType
};
```

但 SysY 语言中的类型要远比上面的基础类型复杂，例如数组类型中还需要考虑元素类型以及元素数量。因此，我们可以用一个类来表示具体的类型，这些类型都继承自一个抽象的`Type`基类。在将 SysY 语言翻译到 LLVM IR 的过程中，你至少需要考虑以下四种类型：

- 基本类型：例如 `int`、`void`
- 数组类型`ArrayType`：例如 `int[10]`、`int[10][10]`, 需要存储数组元素的类型以及元素数量
- 函数类型`FunctionType`：例如 `int f(int a, int b)`，需要存储其返回类型以及每个参数的类型；在大作业中，返回值类型只能是基本类型
- 指针类型`PointerType`：例如 `int *`、`int **`，需要存储指针指向的类型

下面是一个可供参考的设计，同学们可以自行设计类型系统的实现方式，但希望大家能采用良好的、具备可扩展性的软件设计，起码不要都用字符串来表示。

**Type.h**

```c++
/**
 * Array can be represented as [elementCount x elementType], e.g. [3 x i32].
 * elementType: the type of the array element
 * elementCount: represent the length of the array
 * e.g. [3 x [2 x i32]]: an array of length 3, the array element type is a 32-bit signed array of length 2
 * equivalent to int[3][2] in C / C++.
 */
class ArrayType : public Type {
public:
  ArrayType(Type *elementType, uint64_t elementCount)
      : Type(ArrayTypeID), elementType(elementType),
        elementCount(elementCount) {}

  std::string toString() const override;

  Type *getElementType() const { return elementType; }
  uint64_t getElementCount() const { return elementCount; }

private:
  Type *elementType;
  uint64_t elementCount;
};
```

在此之外，我们额外花一点篇幅讲一讲类型系统的注意点。

- 像基本类型`int`、`void`，我们可以设计成 **单例模式** (Singleton Pattern)，避免创建重复的类型。`int`类型可以存储一个参数表示的位数，例如`int1`、`int32`、`int64`。
- 对于其他复杂的类型，其构造比较麻烦，我们可以用 **工厂** (Factory) 的思想来创建对象，在 C / C++ 中，你还需要考虑如何不产生内存泄漏。对于一个 C++ 程序员，只管 new 不管 delete 是一件很糟糕的事情。你可以参考 LLVM 的设计，也可以根据实际大作业的需求设计更简化的版本，例如使用智能指针管理内存。

### IRBuilder

`IRBuilder` 是 LLVM 中用于生成 IR 的类，它提供了一系列的函数，用于生成各种 IR 节点。虽然你可以直接在 YourVisitor 类遍历的过程中直接生成 LLVM IR 的字符串，就像在完成 PA3 时一样，但为了代码的可读性、可扩展性，我们建议你实现 IRBuilder 来生成内存形式的IR。实际上，也只有这样，才能在后续构造控制流图、数据流图，进行中间代码优化以及编译器后端的指令选择、寄存器分配。添加一个 `IRBuilder` “中间层”的设计思想在复杂软件设计中非常重要，IRBuilder 也可以被视为 **建造者模式**（Builder Pattern）的一种实现。

（助教提供的文档只是一种可行的设计，你可以完全不遵守）

你的设计不必与 LLVM 相同，你可以自由设计`Instrcution`的派生类，例如考虑设计不同的`AddInstruction`和`SubInstruction`还是将其统一为`CalcInstruction`，甚至只有一个`Instruction`类，通过`InstType`来区分不同的指令。但是我们不推荐你直接使用字符串来表示指令，这不符合面向对象的封装逻辑，也对后续编译优化和项目维护带来困难。

除了上面大语言模型对 LLVM `IRBuilder`的介绍外，你还可以参考 LLVM Java API 的设计。希望这些内容对大家设计编译器有所帮助。

**LLVM IRBuilder Java API**

```
// 创建module
LLVMModuleRef module = LLVMModuleCreateWithName("module");

// 创建IRBuilder
LLVMBuilderRef builder = LLVMCreateBuilder();

// 获取int32基本类型
LLVMTypeRef i32Type = LLVMInt32Type();

//创建一个常量,这里是常数0
LLVMValueRef zero = LLVMConstInt(i32Type, 0, /* signExtend */ 0);

//创建名为globalVar的全局变量
LLVMValueRef globalVar = LLVMAddGlobal(module, i32Type, /*globalVarName:String*/"globalVar");

//为全局变量设置初始化器
LLVMSetInitializer(globalVar, /* constantVal:LLVMValueRef*/zero);

//生成返回值类型
LLVMTypeRef returnType = i32Type;

//生成函数参数类型
PointerPointer<Pointer> argumentTypes = new PointerPointer<>(2)
            .put(0, i32Type)
            .put(1, i32Type);

//生成函数类型
LLVMTypeRef ft = LLVMFunctionType(returnType, argumentTypes, /* argumentCount */ 2, /* isVariadic */ 0);
//若仅需一个参数也可以使用如下方式直接生成函数类型
ft = LLVMFunctionType(returnType, i32Type, /* argumentCount */ 1, /* isVariadic */ 0);

//生成函数，即向之前创建的module中添加函数
LLVMValueRef function = LLVMAddFunction(module, /*functionName:String*/"function", ft);

//通过如下语句在函数中加入基本块，一个函数可以加入多个基本块
LLVMBasicBlockRef block1 = LLVMAppendBasicBlock(function, /*blockName:String*/"block1");

LLVMBasicBlockRef block2 = LLVMAppendBasicBlock(function, /*blockName:String*/"block2");

//选择要在哪个基本块后追加指令
LLVMPositionBuilderAtEnd(builder, block1);//后续生成的指令将追加在block1的后面

//获取函数的参数
LLVMValueRef n = LLVMGetParam(function, /* parameterIndex */0);

//创建add指令并将结果保存在一个临时变量中
LLVMValueRef result = LLVMBuildAdd(builder, n, zero, /* varName:String */"result");

//跳转指令决定跳转到哪个块
LLVMBuildBr(builder, block2);

//生成比较指令
LLVMValueRef condition = LLVMBuildICmp(builder, /*这是个int型常量，表示比较的方式*/LLVMIntEQ, n, zero, "condition = n == 0");
/* 上面参数中的常量包含如下取值
    LLVMIntEQ,
    LLVMIntNE,
    LLVMIntUGT,
    LLVMIntUGE,
    LLVMIntULT,
    LLVMIntULE,
    LLVMIntSGT,
    LLVMIntSGE,
    LLVMIntSLT,
    LLVMIntSLE,
*/
//条件跳转指令，选择跳转到哪个块
LLVMBuildCondBr(builder, 
/*condition:LLVMValueRef*/ condition, 
/*ifTrue:LLVMBasicBlockRef*/ ifTrue, 
/*ifFalse:LLVMBasicBlockRef*/ ifFalse);

LLVMPositionBuilderAtEnd(builder, block2);//后续生成的指令将追加在block2的后面

//函数返回指令
LLVMBuildRet(builder, /*result:LLVMValueRef*/result);

LLVMPositionBuilderAtEnd(builder, block1);

//int型变量
//申请一块能存放int型的内存
LLVMValueRef pointer = LLVMBuildAlloca(builder, i32Type, /*pointerName:String*/"pointer");

//将数值存入该内存
LLVMBuildStore(builder, zero, pointer);

//从内存中将值取出
LLVMValueRef value = LLVMBuildLoad(builder, pointer, /*varName:String*/"value");


//数组变量
//创建可存放200个int的vector类型
LLVMTypeRef vectorType = LLVMVectorType(i32Type, 200);
```

### 符号表

在 PA4 中，你已经设计了一个符号表，在大作业中的符号表与 PA4 中的符号表类似，都需要考虑作用域的问题。不过，你需要考虑得更细致一些，进入函数、if语句等节点中，作用域都会改变。

符号表里存什么呢？你需要存 LLVM 中的 Value，还可能要存一些类型信息，这个就交给你自己设计啦。
