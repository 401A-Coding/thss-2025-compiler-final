# 项目实现思路

本文档详细介绍本仓库中 SysY 语言编译器前端的实现思路与关键技术点。本编译器以 **C++17** 实现，借助 **ANTLR4** 完成词法与语法分析，将 SysY 语言源码翻译为 **LLVM IR** 文本。

## 1. 整体架构

编译器整体采用“前端三段式”设计：**词法/语法分析 → 语义信息管理（类型、符号表）→ IR 生成**。

```
SysY 源码
   │
   ▼
SysYLexer / SysYParser（ANTLR4 生成）   词法、语法分析，产生语法树
   │
   ▼
      │
      ├── Type       类型系统（int/void/数组/函数/指针）
      ├── SymbolTable  符号表（作用域栈）
      │
      ▼
SysYIRGenerator（继承 BaseVisitor）      遍历语法树，完成语义翻译
   │
   ▼
IRBuilder                        逐条拼接 LLVM IR 文本
   │
   ▼
输出 .ll 文件
```

各模块职责如下：

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 入口 | `src/main.cpp` | 读取输入文件、构建词法/语法分析器、串联各模块、写出 IR |
| 词法规则 | `SysYLexer.g4` | 定义 SysY 关键字、运算符、整数（八/十/十六进制）、注释与空白 |
| 语法规则 | `SysYParser.g4` | 定义 AST 文法，包括常量/变量声明、函数、控制流、完整表达式优先级 |
| 类型系统 | `include/Type.h` | 用继承体系描述 `int`、`void`、数组、函数、指针类型 |
| 符号表 | `include/Symbol.h`、`include/SymbolTable.h`、`src/SymbolTable.cpp` | 管理作用域、符号定义与查找，预加载 sylib 库函数 |
| IR 生成 | `include/SysYIRGenerator.h`、`src/SysYIRGenerator.cpp` | 遍历语法树，把每种语法结构翻译为 IR |
| IR 拼接 | `include/IR.h`、`src/IR.cpp` | 提供逐条 IR 指令生成接口，维护模块/函数/基本块状态 |

> 设计取舍：本项目没有像 LLVM 那样用面向对象的“指令对象”表示 IR，而是由 `IRBuilder` 直接拼接 IR 文本字符串。这样实现更轻量，且便于在生成的同一时刻做常量折叠；代价是不方便再对指令对象做后续优化，但对于课程大作业的前端目标足够。

## 2. 词法与语法分析（ANTLR4）

### 2.1 词法规则（`SysYLexer.g4`）

- 关键字：`const`、`int`、`void`、`if`、`else`、`while`、`break`、`continue`、`return`。
- 运算符：算术（`+ - * / %`）、关系（`< > <= >=`）、相等（`== !=`）、逻辑（`&& || !`）、赋值 `=`。
- 整数字面量分三种：
  - 八进制：`'0' [0-7]*`
  - 十进制：`[1-9] [0-9]*`
  - 十六进制：`'0' [xX] [0-9a-fA-F]+`
- 空白与注释（`//`、`/* */`）通过 `-> skip` 直接跳过，不进 token 流。

### 2.2 语法规则（`SysYParser.g4`）

语法采用贴近 SysY 定义的层级式表达，优先级由规则嵌套顺序天然体现：

```
primaryExp → unaryExp → mulExp → addExp → relExp → eqExp → lAndExp → lOrExp
（单目 → 乘除模 → 加减 → 关系 → 相等 → 逻辑与 → 逻辑或）
```

- 变量/常量定义支持 `IDENT (下标)*` 的数组维数形式，索引、初始化值使用 `constExp`。
- 函数形参支持 `bType IDENT arrayDim?`，其中 `arrayDim` 以 `[]` 开头，后接指定维度，用于表达“数组退化指针”参数（如 `int a[][N]`）。
- 语句覆盖：赋值、表达式、块、`if/else`、`while`、`break`、`continue`、`return`。
- 使用 ANTLR 的 **Alternative Labels**（如 `# VarDefNoInit`、`# BinaryAddExp`），使每个语法形态对应独立的 Visitor 方法，代码结构清晰。

## 3. 类型系统设计（`include/Type.h`）

类型用继承体系实现，抽象基类 `Type` 提供：

- `toIRString()`：输出对应的 LLVM IR 类型字符串，如 `i32`、`[3 x i32]`、`i32*`。
- 若干类型判定虚函数：`isNumericType()`、`isPointerType()`、`isArrayType()`。

| 类型 | 对应 SysY | LLVM IR 表示 | 设计要点 |
| --- | --- | --- | --- |
| `IntType` | `int` | `i32` | **单例模式**，全局共享 |
| `VoidType` | `void` | `void` | 单例模式 |
| `ArrayType` | `int[2][3]` | `[2 x [3 x i32]]` | 嵌套递归表示多维；提供 `fromDims()` 便捷构造 |
| `FunctionType` | `int f(int, int)` | `i32 (i32, i32)` | 存返回类型与参数类型列表 |
| `PointerType` | `int*`、`int(*)[N]` | `i32*`、`[N x i32]*` | 存指向类型，用于数组参数退化 |

使用 `std::shared_ptr` 管理类型对象生命周期，避免手写 `new/delete` 造成内存泄漏。

## 4. 符号表设计（`Symbol.h` / `SymbolTable.h`）

### 4.1 符号种类（`SymbolKind`）

- `VARIABLE`：变量，`VariableSymbol` 区分全局/局部与是否为形参，IR 名称分别为 `@var_N` / `%var_N`。
- `FUNCTION`：函数，`FunctionSymbol` 记录是否系统库函数，IR 名称固定为 `@函数名`。
- `CONSTANT`：常量，`ConstantSymbol` 保存编译期计算出的 IR 值（如 `i32 10`），在参与运算时直接内联数值，不生成 SSA。

### 4.2 作用域管理

`SymbolTable` 内部使用 `std::stack<unordered_map<name, Symbol>>` 表示作用域栈：

- `enterScope()` / `exitScope()`：进入/退出块或函数作用域，全局作用域不可退出。
- `findSymbol()`：从栈顶（当前作用域）逐层向下查找，实现“就近遮蔽”语义。
- 每个作用域是一张哈希表，保证当前作用域内名字唯一；重名插入返回 `false`。

### 4.3 预加载 sylib 库

`loadSysLibSymbols()` 在构造符号表时预先登记 6 个 SysY 运行库函数签名（`getint`、`getch`、`getarray`、`putint`、`putch`、`putarray`），使编译器在未见到函数定义时即可解析这些调用。

## 5. IR 生成（`SysYIRGenerator.cpp`）

`SysYIRGenerator` 继承 `SysYParserBaseVisitor`，用 **Visitor 模式** 自顶向下遍历语法树。每一类语法节点重写对应的 `visitXxx` 方法，借助符号表查类型、借助 `IRBuilder` 发指令。

### 5.1 编译单元与库函数声明

`visitCompUnit` 首先通过 `irBuilder->declareFunction(...)` 在模块头部输出 6 个 sylib 函数的 `declare` 原语，然后遍历所有顶层定义。

### 5.2 常量与变量定义

**常量（`visitConstDef`）**

- 先解析数组维度并对其中的 `constExp` 做 **常量折叠**（见 5.6）。
- 标量常量：生成 `ConstantSymbol` 存入符号表；全局作用域下额外生成 `@const_N = constant i32 ...`。
- 常量数组：全局时把初始化列表扁平化、按行主序补齐后生成嵌套 `constant` initializer；局部时 `alloca` 数组并逐元素 `store`。

**变量（`visitVarDefNoInit` / `visitVarDefWithInit`）**

- 局部变量一律通过 `createAllocaInEntry` 分配到**函数入口基本块**，避免循环体内反复 `alloca` 导致栈空间爆炸。
- 全局标量：默认 `0`；全局数组：默认 `zeroinitializer`。
- 局部数组初始化：将嵌套 `{...}` 初始化列表扁平化为行主序一维序列，缺省补 `0`，再对每个元素用 GEP 计算地址后 `store`。
- 全局数组初始化：扁平化后生成与数组类型精确匹配的嵌套 initializer 字符串（如 `[i32 1, i32 2]`），一次 `global` 指令完成。

### 5.3 函数翻译

`visitFuncDef` 的处理流程：

1. 解析返回类型（`int`/`void`）与形参。**数组形参**（如 `int a[][N]`）退化为指针类型 `[N x i32]*`；仅 `[]` 时退化为 `i32*`。
2. 构造 `FunctionSymbol` 插入符号表，输出 `define 返回类型 @函数名(形参声明) {`。
3. 进入函数作用域；为每个形参 `alloca` 局部空间并把 `%arg_形参名` 存入，使函数体内可以统一按“变量”读写。
4. 访问函数体 `block`，若为 `void` 函数且函数体未显式 `return`，自动补 `ret void`。
5. 退出作用域、闭合函数。

### 5.4 控制流翻译

**`if/else`**：生成 `then` / `else`（可选） / `endif` 三个基本块。条件求值得到 `i1` 后发 `cond br`，两个分支末尾跳回 `merge` 块。

**`while`**：生成 `while_cond` → `while_body` → `while_end`。`break` 跳到当前循环 `end` 块、`continue` 跳到当前循环 `cond` 块，分别用两个栈 `breakBBs` / `continueBBs` 支持嵌套。

**基本块自动终结**：`startBasicBlock` 若发现上一个基本块没有终结指令，会自动补一条 `br label %新块`；`endBasicBlock` 若仍未终结则补 `unreachable`，保证 IR 合法。

### 5.5 表达式与短路求值

**算术/一元**：`+ - * / %` 分别映射为 LLVM 的 `add nsw / sub nsw / mul nsw / sdiv / srem`；一元 `-` 用 `0 - x` 实现，`!` 用 `icmp eq` + `zext` 实现。

**条件表达式专用（`cond` 链）**：关系/相等比较产生 `i1`，逻辑与、逻辑或实现**短路求值**：

- `a && b`：左侧为假直接为假；否则求右侧。
- `a || b`：左侧为真直接为真；否则求右侧。

短路通过“条件跳转 + phi 合并”实现。例如 `a || b`：

```
br i1 %a, label %or_true, label %or_rhs
or_rhs:
  %b_i1 = ...
  br label %or_merge
or_true:
  br label %or_merge
or_merge:
  %result = phi i1 [ 1, %or_true ], [ %b_i1, %or_rhs ]
```

**i1/i32 类型追踪**：逻辑层与数值层混用时需要区分 `i1` 与 `i32`。生成器维护 `i1Values` 集合，记录所有已知为 `i1` 的 SSA 名：

- `toI1FromIntLike`：若值已是 `i1` 直接使用，否则生成 `icmp ne i32 val, 0` 转换为 `i1`。
- `ensureI32`：若值是 `i1`，则 `zext i1 → i32`，用于参与数值比较/运算（如相等性比较统一到 `i32` 再做 `icmp eq`）。

### 5.6 常量折叠与数字规范化

- `evaluateConstExp`：在编译期递归求值常量表达式，支持标识符常量引用、括号、一元正负/逻辑非与 `+ - * / %` 运算，返回形如 `"i32 10"` 的 IR 文本，从而避免为常量生成多余 SSA 指令。
- `normalizeIntLiteral`：把 ANTLR 得到的整数字面量按 **十六进制（0x）**、**八进制（前导 0）**、**十进制** 统一规范化为十进制字符串。

### 5.7 数组与指针

- **取值**（表达式位置的 `lVal`）：数组变量按“数组类型 + 首索引 0”的 GEP 取元素地址后 `load`；多下标依次展开。数组名作为值时通过 GEP `0,0,...` **退化为首元素指针**。
- **赋值**（`visitAssignStmt`）：标量直接 `store`；数组元素先 GEP 再 `store`；指针变量先 `load` 指针值，再按指向类型做不含首 0 的 GEP。
- **实参传递**：向指针形参传数组时，根据目标形参类型（`i32*` 或 `[N x i32]*`）自动决定 GEP 到达的层级——`i32*` 深入到最内层元素，`[N x i32]*` 则只下钻到行级别。该逻辑支持数组作为参数的“退化”语义。

## 6. IRBuilder 设计（`IR.h` / `IR.cpp`）

`IRBuilder` 以缓冲区 `irBuffer` 为核心，维护 `inFunction`、`inBasicBlock`、`bbTerminated` 三个状态标志，提供约 20 个指令级接口：

| 类别 | 接口 |
| --- | --- |
| 模块/函数/块 | `startModule`、`startFunction`、`startBasicBlock`、`endBasicBlock`、`endFunction`、`endModule` |
| 存储 | `createGlobalVar`、`createGlobalConst`、`createAlloca`、`createAllocaInEntry`、`createStore`、`createLoad` |
| 运算 | `createBinaryOp`、`createICmp`、`createZExt`、`createPhi` |
| 寻址 | `createGEP`（支持索引列表与多维下标两种重载） |
| 控制流 | `createBr`、`createCondBr`、`createReturn`、`createCall` |
| 声明 | `declareFunction` |

**入口块 alloca 提升**：`createAllocaInEntry` 会把指令缓存到 `entryPrologueBuffer`，待 `startBasicBlock("entry")` 时统一插入到 entry 标签之后；若 entry 块已开始，则直接插入到记录的偏移 `entryInsertOffset` 处。这一机制把循环体内声明的变量提升到函数入口，避免循环每次迭代都执行 `alloca` 造成栈空间浪费。

## 7. 运行流程：`src/main.cpp`

```
命令行解析（argv[1] 输入 .sy，argv[2] 输出 .ll）
   → 打开输入文件
   → ANTLRInputStream → SysYLexer → CommonTokenStream → SysYParser
   → parser.compUnit() 得到语法树
   → 创建 SymbolTable / IRBuilder / SysYIRGenerator
   → startModule → visit(tree) → endModule
   → 将 irBuffer 字符串写入输出文件
```

## 9. 关键难点与解决思路小结

1. **短路求值**：用基本块划分 + phi 合并实现 `&&` / `||`，借助 `i1Values` 追踪 `i1` 类型避免类型错配。
2. **数组初始化**：嵌套花括号初始化统一“扁平化 → 行主序补零 → GEP+store（或嵌套 initializer）”处理，兼容多维与缺省初始化。
3. **数组参数退化**：形参 `int a[][N]` 映射为 `[N x i32]*`，实参传递时按目标指针层级精确控制 GEP，保证类型正确。
4. **循环内局部变量栈安全**：`alloca` 提升至入口块，防止循环体反复分配导致栈溢出。
5. **IR 合法性**：基本块缺失终结指令时自动补 `br` 或 `unreachable`，保证输出可被 `clang` 正常解析。
